# 뷰어 구조

빌드 단계가 없는 ES 모듈 앱입니다. `index.html` 이 `src/main.js` 를 불러오고, 의존 라이브러리는 없습니다(WebGL2 필요).

## 파일

## 렌더 순서

합성은 전부 지도 해상도(또는 그 2배)의 오프스크린 버퍼에서 텍셀 단위로 합니다. 화면 해상도에서 합성하면 픽셀아트의 격자와 깊이 비교가 어긋납니다.

1. **바탕**: 배경 그림에 계절 변환(잔디·나무 색, 눈)을 입히고, 나무 흔들림과 물결을 적용합니다. 둘 다 클래스 맵으로 대상을 고르고, 그림 픽셀 단위로만 움직입니다.
2. **그림자와 스프라이트**: 차·사람·새를 그립니다. 스프라이트의 각 픽셀 깊이를 배경 깊이와 비교해, 건물 뒤에 있으면 버립니다. 이것이 "차가 건물 뒤로 지나간다"의 전부입니다.
3. **빛**: 가로등·전조등의 빛 웅덩이를 절반 해상도에 더합니다.
4. **조명 합성**: 낮밤 색, 구름 그림자, 궁궐 야간 조명, 창문 불빛. 창문은 벽 클래스 픽셀 중 푸른 유리색인 곳만, 층·칸 단위 난수로 켭니다.
5. **화면**: 카메라 변환, 확대 시 또렷한 픽셀 유지, 눈·비, 틸트시프트(화면 위아래를 흐리게, 가까이 확대하면 꺼짐).

### 확대 단계(타일)

`tiles/manifest.json` 이 있으면 배경은 타일 경로로 그립니다. 처음에는 `z1.png` 한 장만 받고, 확대하면 화면에 걸친 타일만 받아 옵니다.

- 화면 배율(지도 px 당 기기 px)이 2·4·8 에 닿으면 z2·z4·z8 로 올라갑니다(내려갈 때는 그 0.9배까지 유지). 데스크톱은 합성 창 예산이 넉넉해 배율 1 을 넘으면 z2 를 씁니다. 타일이 도착하기 전에는 이미 있는 거친 단계로 채우고, 화면에 필요한 타일이 다 오면 한 번에 바꿉니다.
- z2 이상에서는 지도 전체가 아니라 화면에 보이는 창만큼만 오프스크린 버퍼를 만들어 합성합니다(휴대폰 최대 2048², 데스크톱 4096×2560 텍셀).
- 깊이·클래스 맵은 0.5 m/px 그대로입니다. 그래서 깊은 단계에서는 클래스 경계가 그림 윤곽과 한두 텍셀 어긋날 수 있어, 계절 변환·흔들림·물결·궁궐 조명은 클래스에 더해 그림 색(초록·파랑·기와색)으로 대상을 다시 가립니다. 그림자는 지도 px 해상도로 한 번 구해 부드럽게 읽습니다.
- 차·사람·새는 z4·z8 에서 그 해상도로 다시 그린 아틀라스를 씁니다(스프라이트 kind 7~10). 아틀라스가 준비되기 전에는 기본 스프라이트를 그대로 씁니다.
- 최대 확대는 가장 깊은 단계 텍셀의 4배(z8 이면 화면 배율 32)입니다.
- z4·z8 에서 깊이·클래스 맵을 읽는 효과는 0.5 m 칸이 덩어리로 보이지 않게 다음처럼 처리합니다(z1·z2 는 그대로).
  - 표면 버퍼: 지도 px 마다 "윗면(눈이 얹히는 면)", "평지(그림자를 받는 땅)", "둘레의 윗면 비율"을 구해 작은 버퍼에 담습니다(창 영역만, 화면이 움직일 때만 다시 그림). 이웃 3×3 칸을 바탕 그림 색이 비슷한 칸끼리 평균해 한두 칸짜리 낱알을 거릅니다.
  - 텍셀마다 둘러싼 네 칸을 "가까운 정도 × 그림 색이 비슷한 정도"로 섞어 반에서 끊습니다. 색이 갈리는 곳에서는 경계가 그림의 선을 따르고, 같은 색 안에서는 그 단계 텍셀의 매끈한 선이 됩니다.
  - 겨울 눈: 평지는 고른 눈밭에 세 단의 옅은 결, 수관은 그림에서 밝게 칠한 텍셀에만, 지붕·기단은 윗면에만 얹습니다. 궁궐의 붉은 벽·회벽·창살은 벽으로 남깁니다.
  - 그림자·접지 음영: 지도 px 버퍼를 다섯 번 읽어 고르고 계단값으로 다시 끊습니다. 받는 면은 위의 "평지" 값입니다.
  - 창문 불빛: 층 높이와 깊이를 같은 벽면의 네 칸에서 보간해 층 선이 벽면을 따라가는 곧은 선이 됩니다. 켜짐 칸은 가로 2 m × 층이라 유리 한 장이 세로선·층 선에서 나뉠 수는 있습니다(그림의 창틀과 맞추지는 않음).
  - 밤 궁궐 조명은 벽·기둥을 주로 비추고, 밝은 윗면(기단 바닥·계단·눈)은 약하게만 받습니다.
- 수관 마스크 `assets/redraw/crown.png`(선택, 없으면 클래스 맵대로): 그림을 다시 그리며 나무 자리가 바뀌어 클래스·깊이 맵의 나무와 그림이 어긋난 곳을 바로잡습니다. R 은 칸(0.5 m)에서 수관이 덮는 비율(0 = 정보 없음, 1 = 나무 없음, 2~255), G 는 나무 한 그루 단위 색 번호입니다. 렌더러(`semC`)는 수관이 칸의 4할 넘게 덮은 칸만 수목으로 보고, 마스크가 "나무 없음"이라 한 수목 칸은 녹지로 봅니다. 단풍·벚꽃 색은 그루 번호로 골라 한 그루가 한 색이 됩니다. `tools/redraw/make_crown.py` 가 z8 타일에서 굽습니다(타일을 바꾸면 다시 구워야 합니다. 약 40초).
- 깊이·클래스 맵 PNG 는 브라우저 디코더에 맡기지 않고 `src/png.js` 로 직접 풉니다. 사파리(WebKit)는 회색조 PNG 를 색 변환해 클래스 값(0~11)을 다른 수로 바꾸는데, 그러면 밤 조명·창문 불빛·눈이 0.5 m 칸 단위 점무늬로 흩어집니다.

깊이는 근사값입니다. 가림이 어색한 곳은 「검증 도구」의 오버레이로 볼 수 있습니다.

## 장면 데이터 형식

`scene.json.gz` 의 주요 키. 좌표는 로컬 미터(x, y, z).

```jsonc
{
  "camera": { "res": [2752, 1696], "m_per_px_screen": 0.5, "cx": …, "cy": …, "cam_location": […],
              "view_dir": […], "screen_x_axis": […], "screen_y_axis": […] },
  "lanes":   [{ "id": "E000", "name": "자하문로", "highway": "primary", "oneway": false,
                "lanes_dir": 2, "length": 938.47, "spawn": false, "exit": true, "stopline": false,
                "pts": [[x, y, z], …] }],
  "walkers": [{ "id": "W0000", "speed_mps": 1.26, "length_m": 20.1, "pts": [[x, y, z], [x, y, z]] }],
  "walker_palette": [["#shirt", "#pants", "#hair"], …], "walker_pal_idx": [222, …],
  "standing": [{ "x": …, "y": …, "z": 0, "facing": 0, "pal": 6 }],
  "vehicle_specs": { "sedan": [길이, 폭, 높이], "bus": […], … },
  "vehicle_atlas": { "headings": 32, "frames": [{ "kind": "bus", "color": "#2f6fd0" }, …] }
}
```

차선은 OSM 도로 중심선을 방향별 차선으로 나눈 것이고, 교차로 연결·신호·양보 구역은 `traffic.js` 가 시작할 때 차선 형상에서 계산합니다.

## 주소 옵션

| 옵션 | 뜻 |
|---|---|
| `#x,y,vh` | 지도 px 중심과 보이는 높이로 바로 이동. `&t=시각`, `&s=계절(0~3)` 을 붙일 수 있음 |
| `?res=1` | 절반 해상도 그림(타일을 쓰지 않을 때) |
| `?tiles=0` | 타일을 쓰지 않고 통짜 그림으로(이전 동작) |
| `?maxlod=2\|4\|8` | 쓸 가장 깊은 타일 단계 제한 |
| `?cars=N` | 차량 수 |
| `?tod=시각`, `?season=0~3` | 시작 시각(시간 흐름 정지), 계절 |
| `?tilt=0` | 틸트시프트 끄기 |
| `?tour` | 자동 둘러보기로 시작 |
| `?clean` | UI 숨김(녹화용) |
| `?seed=N`, `?birdseed=N` | 교통·새 배치 난수 |

## 테스트와 캡처

```bash
npm test                                   # 투영, 교통 불변식(겹침 없음, 정체 해소 등), 새 로직
node tools/shot.mjs out.png "clean" "window.__iso.cam.set(800,1200,260),1" 1440 900 3
MOBILE=1 DPR=2 node tools/shot.mjs phone.png "clean" "window.__iso.cam.set(800,1200,105),1" 390 844 3   # 휴대폰 에뮬레이션
node tools/capture.mjs tour.mp4            # 둘러보기를 프레임 단위로 결정론적 녹화
```

`window.__iso` 에 캡처·테스트용 손잡이가 있습니다: `manual(true)` 뒤 `step(dt)` 로 한 프레임씩 진행, `cam.set(x, y, vh)`, `state`(시각·계절), `traffic`, `birds`.

테스트가 보지 못하는 것: 셰이더 출력. 화면에 사람·차·새가 실제로 그려지는지는 스크린샷으로 확인해야 합니다.

## 휴대폰과 인앱 브라우저

트위터 같은 앱 안의 브라우저(iOS WKWebView, Android WebView)에서 열리는 것을 기준으로 맞췄습니다.

- 휴대폰에서는 타일 아틀라스를 96칸(데스크톱 256칸), 합성 창을 2048² 텍셀 이하로 잡습니다. 타일이 없는 배포에서는 절반 해상도 그림을 씁니다(`?res=2` 로 강제 가능).
- GPU 메모리 추정(텍스처·버퍼 합, 헤드리스 크롬의 390×844 dpr 2 에뮬레이션에서 계산한 값이며 실제 기기 측정이 아님): 타일 없이 약 119 MiB, z2 약 158, z4 약 162, z8 약 175 MiB.
- 안전판: z4·z8 을 그리던 중에 그래픽 컨텍스트를 잃거나 탭이 죽었다 다시 열리면, 그 탭에서는 다음부터 한 단계 얕게만 씁니다(`sessionStorage`). 헤드리스 크롬에서 컨텍스트 손실과 남은 표시로 확인했고, 실제 기기에서 탭이 죽는 상황으로는 확인하지 못했습니다.
- 장면 데이터는 비압축 `scene.json` 을 먼저 읽습니다. `DecompressionStream` 이 없는 구형 브라우저에서도 열리게 하기 위해서입니다.
- 화면 높이는 `100dvh` 와 safe-area 여백을 씁니다. 앱 안 브라우저는 위아래에 자체 바가 있어 `100vh` 가 맞지 않습니다.
- 캔버스는 `touch-action: none` 이라 당겨서 새로고침이나 페이지 확대가 지도 조작을 가로채지 않습니다.
- 소리는 기본 꺼짐이고, 버튼을 누른 뒤에만 재생됩니다.
- WebGL2 를 쓸 수 없으면 정지 그림과 안내 문구를 보여 줍니다.
