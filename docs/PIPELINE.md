# 그림을 만드는 절차

> **지금 공개된 그림은 이 문서의 방식으로 만든 것이 아닙니다.** 2026-11-11 부터 그림은 Blender 3D 장면의 렌더를 이미지 편집 모델로 양식만 바꿔 만듭니다(요약은 저장소 README 의 "어떻게 만들었나"). 아래는 그 전 판(깊이와 OSM 으로 만든 2D 색 블록 밑그림을 타일 단위로 다시 그리는 방식)의 절차이고, `pipeline/` 의 스크립트도 그 판의 것입니다. 타일 생성·검사·병합의 생각은 그대로 쓰였지만, 밑그림·랜드마크 합성·2×2 픽셀 격자 정리(96색)는 지금 그림에 쓰이지 않았습니다.

`pipeline/` 의 스크립트로 배경 그림 한 장(5504×3392, 0.25 m/px)과 뷰어용 보조 맵을 만드는 과정입니다.
명령은 저장소 루트에서 실행합니다. 작업 폴더(`work/`)는 gitignore 대상이고, 중간 산출물은 커밋하지 않습니다.

## 준비물

| 무엇 | 설명 |
|---|---|
| Python 3.10+ | `pip install numpy pillow` |
| 생성 장비 | ComfyUI 가 도는 GPU 장비. ssh 로 접속합니다. 여기서는 통합 메모리 약 120 GB 장비 한 대를 썼고, 모델은 약 30 GB 를 씁니다 |
| 모델 | `qwen_image_edit_2511_fp8mixed.safetensors`, `qwen_2.5_vl_7b_fp8_scaled.safetensors`, `qwen_image_vae.safetensors`, `Qwen-Image-Edit-2511-Lightning-8steps-V1.0-bf16.safetensors` (Comfy-Org 재패키징과 lightx2v 배포본) |
| 입력 | 카메라 정의(`pipeline/input/camera_nw45w.json`), 그 카메라로 렌더한 깊이(`pipeline/input/occlusion_depth16.png`), OSM 데이터 |

환경 변수로 장비를 지정합니다.

```bash
export GEN_SSH_HOST=mybox                 # ssh 별칭
export GEN_REMOTE_DIR=/path/on/box/redraw # 그 장비의 작업 폴더(in/, out/ 이 생깁니다)
```

`pipeline/gen_server.sh` 는 그 장비에서 ComfyUI 컨테이너를 띄우고 내리는 예시입니다. 경로와 이미지 이름은 장비에 맞게 고쳐 쓰세요.
GPU 가 이미 쓰이고 있거나 다른 컨테이너가 떠 있으면 뜨지 않게 해 두었습니다(공용 장비에서 남의 작업을 밀어내지 않도록).

## 좌표와 카메라

- 정사투영, 북서쪽을 바라보고 수평에서 35° 내려다봅니다. 화면 1 px = 0.5 m("지도 px"). 엄밀한 아이소메트릭은 아닙니다.
- 캔버스는 2752×1696 지도 px. 최종 그림은 그 2배(0.25 m/px), 생성은 4배(0.125 m/px)로 합니다.
- 월드 좌표는 EPSG:5186 에서 원점을 뺀 로컬 미터, z 가 위입니다.
- 깊이는 16비트 PNG: `depth_m = 2060 + value × 0.02`, 65535 는 "없음".
- 투영식과 깊이 복원은 `src/geom.js` 와 `pipeline/make_guide.py` 앞부분에 있습니다.

모든 단계가 이 카메라 하나를 공유합니다. 그래서 밑그림·그림·깊이·클래스 맵이 픽셀 단위로 겹칩니다. 이것이 전체 방식의 핵심입니다.

## 단계

### 1. OSM 받기

```bash
python3 pipeline/fetch_osm.py work/osm_raw.json
```

Overpass 에서 건물·도로·수면·녹지·궁궐 경계를 받습니다. 범위는 스크립트 위쪽의 경위도 상자입니다.

### 2. 블록 밑그림 만들기

```bash
python3 pipeline/make_guide.py work/guide work/osm_raw.json
```

출력:

| 파일 | 내용 |
|---|---|
| `guide_color.png` | 모델에 넣는 의미색 블록 그림. 도로에는 차선 점선을 그려 둡니다 |
| `guide_classes.png` | 픽셀별 클래스(0 없음, 1 지면, 2 도로, 3 잔디, 4 물, 5 궁궐 마당, 6 건물 지붕, 7 건물 벽, 8 궁궐 지붕, 9 궁궐 벽, 10 나무, 11 광장·보행로) |
| `guide_kinds.png` | 건물 성격(1 빌라, 2 한옥, 3 중층, 4 타워, 5 아파트, 6 공공, 7 청와대) |
| `guide_bid.png` | 픽셀별 건물 번호(랜드마크 합성에 씀) |
| `depth_rg8.png` | 뷰어용 깊이(R·256+G) |
| `landmarks.json` | 이름으로 찾은 랜드마크의 화면 위치와 건물 번호 |

여기서 하는 일:

- 렌더 깊이를 지면 평면과 비교해 "솟은 것"을 건물로 보고, 깊이 기울기로 지붕과 벽을 나눕니다.
- OSM 폴리곤을 월드 격자에 칠한 뒤 깊이로 화면에 옮겨 도로·잔디·물·나무를 나눕니다.
- 3D 장면 범위 밖의 건물은 OSM 윤곽과 `height`/`building:levels` 태그로 깊이 맵에 직접 세웁니다. 태그가 없으면 면적으로 높이를 어림합니다.
- 건물마다 성격을 정합니다: OSM 태그, 평균 높이, 면적, 동네 구역(북촌·서촌의 낮고 작은 건물은 한옥으로 추정). 성격마다 지붕·벽 색 표가 달라서, 모델이 색을 보고 다르게 그립니다.

### 3. 타일로 나눠 다시 그리기

```bash
bash pipeline/gen_server.sh up     # 생성 장비에서
python3 pipeline/run_tiles.py work/guide work/run1 v1 --seed 23 --scale 4 --ov 128 --retries 2
```

- 밑그림을 4배(NEAREST)로 키워 1408×1024 타일로 자릅니다. 겹침 128 px. 이 지역은 9×8 = 72장, 장당 약 35초였습니다.
- 타일마다 클래스·건물 성격의 비율을 보고 프롬프트를 조립합니다(`pipeline/prompts.py`). 도로가 없는 타일에 도로 문장을 넣지 않는 식입니다.
- 모델 입력은 밑그림 타일 한 장입니다. Lightning 8-step, CFG 1. 워크플로는 `pipeline/gen_run.py` 가 ComfyUI API 형식으로 만듭니다.
- 타일이 돌아오면 색 규칙으로 검사하고 실패분만 시드를 바꿔 다시 돌립니다.
  - 도로 영역 평균이 푸르면 실패("도로를 강으로 칠함")
  - 잔디 영역이 모래색이면 실패
  - 물·건물·빈 곳이 아닌데 파란 픽셀이 0.8% 넘으면 실패("없는 물을 지어냄")

### 4. 색 맞추고 병합

```bash
python3 pipeline/finish.py work/guide work/run1 v1 --scale 4
```

타일마다 톤이 조금씩 달라 조각보처럼 보입니다. 클래스별 평균색을 전체 타일의 중앙값 쪽으로 옮긴 뒤(무늬는 그대로) 좁은 띠(8 px)로 섞어 붙입니다.
넓게 섞으면 서로 다르게 그려진 건물이 반투명하게 겹쳐 보입니다.

### 5. 랜드마크

```bash
python3 pipeline/fetch_refs.py work/refs                      # 위키미디어 공용에서 후보 받기(라이선스 필터)
# 후보를 눈으로 보고 골라 work/refs/refs.json 과 sel_<이름>.jpg 를 만든다
python3 pipeline/landmarks.py work/guide work/lm work/run1/v1_final.png work/run1/v1_lm.png --refs work/refs
```

- 일반 타일은 "한옥", "타워" 같은 종류 설명만 받으므로 광화문도 평범한 기와집으로 나옵니다. 그래서 랜드마크를 창 한가운데에 놓고 따로 그립니다.
- 생김새는 글보다 사진이 잘 전달합니다. 편집 모델의 두 번째 이미지 입력에 참조 사진을 주고, 프롬프트로 "구도와 위치는 1번 그림, 건축은 2번 사진"이라고 나눕니다. 사진은 텍스트 인코더에만 보이고 구도에는 관여하지 않습니다.
- 합성은 그 건물의 픽셀(조금 부풀린 범위)만 바꿉니다. 사진을 따라 그리면 탑이 밑그림보다 높이 솟으므로 위쪽으로 여유를 둡니다(`--up`).
- 작은 건물은 `--zoom 0.5` 로 두 배 확대해 그린 뒤 줄여 붙이면 훨씬 또렷합니다.
- 주변까지 통째로 바꾸는 `--rect` 는 조심해서 씁니다. 모델이 도로에 차를 그려 넣거나 주변에 없는 건물을 지어냅니다. `--keep 2`(도로는 바탕 유지)와 `--match`(클래스별 평균색 맞춤)를 같이 씁니다.
- 참조 사진은 재배포하지 않고, 목록(`pipeline/refs.json`: 제목·저작자·라이선스·주소)만 둡니다.

### 6. 픽셀 격자로 정리하고 설치

```bash
python3 pipeline/snap.py work/run1/v1_lm.png work/v1_snap.png --colors 96
python3 pipeline/install.py work/v1_snap.png work/guide assets/redraw
```

- 모델 출력은 "픽셀아트풍 일러스트"입니다. 원본 크기로 보면 경계가 흐릿합니다.
- 전체에서 96색 팔레트를 뽑아 디더 없이 양자화하고, 2×2 칸마다 가장 많은 색 하나로 채웁니다(동률이면 어두운 색 → 윤곽선이 남음).
- `install.py` 는 지도 밖 영역을 한 색으로 정리하고, 절반 해상도 판과 클래스·깊이 맵을 함께 넣습니다.

## 다른 지역에 적용하기

바꿔야 하는 것, 순서대로:

1. **카메라와 깊이.** 이 저장소에는 3D 장면을 만들고 깊이를 렌더하는 단계가 들어 있지 않습니다(작성 환경의 Blender 작업이라 그대로 돌릴 수 있는 형태가 아닙니다).
   필요한 것은 `camera_*.json` 형식의 정사투영 카메라와 그 카메라로 본 16비트 깊이 한 장입니다.
   가장 간단한 길은 3D 장면 없이 가는 것입니다: 깊이를 지면 평면으로 채워 두면 `make_guide.py` 의 "범위 밖 건물 세우기" 코드가 OSM 윤곽과 높이 태그만으로 모든 건물을 세웁니다. 이 지역의 가장자리 2천여 동이 그렇게 만들어졌습니다.
2. **OSM 범위.** `fetch_osm.py` 의 경위도 상자와 궁궐 경계 관계 번호.
3. **좌표계.** `make_guide.py` 의 `tm5186()` 과 로컬 원점. 한국 밖이면 그 지역의 평면 좌표계로 바꿉니다.
4. **지역 규칙.** 한옥 추정 구역, 건물 성격 기준, 색 표, 랜드마크 이름 표(`LM`). 이 부분이 "그 동네답게" 보이게 하는 곳입니다.
5. **프롬프트.** `prompts.py` 의 종류별 문장. 지역의 건물 유형에 맞게 다시 씁니다.
6. **검사 규칙.** `run_tiles.py` 의 색 기준은 이 그림의 색 표에 맞춰져 있습니다.
7. **뷰어 장면 데이터.** `assets/web-poc/scene.json.gz` 의 차선·보행 경로. 형식은 [APP.md](APP.md)에 있습니다.

## 알려진 한계

- 타일을 따로 그려 붙이므로 타일마다 그림체가 조금 다르고, 겹침 자리에 흔적이 남는 곳이 있습니다.
- 모델이 옥상에 물탱크를, 궁궐 담 옆에 통을 지어냅니다.
- 건물 성격과 한옥 여부의 일부는 추정입니다.
- 랜드마크 26곳 중 재사용 가능한 사진을 찾은 14곳만 사진 참조로 그렸습니다.
